GrabLab CMS v0.2.0 — Plain-English Walkthrough

Exclusive Theme Engine, Reusable Template Parts, Zero-Plugin Native Hooks & Filters, and the Cached Query Loop Engine.

1. What Was Built in v0.2.0

Milestone v0.2.0 transforms GrabLab CMS from a foundational content store into a full themeable publishing engine while keeping its strict zero-plugin security model:

  • Safe Theme Validation & Hot-Switch Engine: Inspects theme folders and package bundles before registration, blocking path traversal (..), sensitive files (.env, .git, .key), executable files (.exe, .sh, .php, .go), oversized packages, and unauthorized capabilities (GRAB-E401).
  • First-Class Visual Theme Contract (mode: "visual"): Alongside coded .grab.html themes (mode: "coded"), GrabLab now natively validates and renders Grex Theme Builder visual themes powered by grex.elements.json and Grex JS v1.0.0.
  • Reusable Template Parts (Zero Wrapper-<div> Bloat): Active themes register header, footer, card, and sidebar parts that render directly as clean HTML5 elements (<header>, <footer>, <article>, <aside>) with zero extra wrapper <div> tags.
  • Native Hooks & Filters Registry: Five priority-ordered lifecycle extension points restricted strictly to GrabLab Core and the single Active Theme.
  • Query Loop Engine & Smart Cache Invalidation: Powers coded archives, /search, and GET /api/query (for Grex useQuery + ForEach) using prepared SQL and automatic use cache epoch invalidation whenever content changes or themes switch.

2. How Exclusive Themes Work

Only one theme can be active at a time. When you switch themes via POST /api/themes/activate:

  • GrabLab validates theme.json, all templates/parts, or grex.elements.json.
  • A database transaction marks all other themes inactive (is_active = 0) and activates the new theme (is_active = 1).
  • All hooks from the old theme are dropped immediately, and use cache epochs bump so visitors see the new theme on the very next page load.

3. Native Hooks & Filters

Hooks run in predictable priority order (lower numbers run first, e.g. 5 before 10):

  • content:before_save — Normalizes titles and auto-fills SEO metadata before saving.
  • content:after_publish — Clears route and Query Loop caches automatically after publishing.
  • theme:head_meta — Injects canonical URLs, OpenGraph tags, and active theme meta tags.
  • theme:before_render — Prepares active theme context before any template renders.
  • query:modify_args — Clamps pagination bounds and enforces published status on public routes.

4. Query Loop Engine (GET /api/query)

Both coded themes and Grex visual ForEach loops fetch filtered, paginated entries safely without raw SQL concatenation:

Parameter Allowed Values Behavior
content_type Any valid type slug (e.g. post, product) Filters entries to a single content type or all types if omitted.
field_key, field_op, field_value eq, neq, contains Filters by custom field values while preserving exact GrabDecimal strings (e.g. 19.9500).
sort_by, sort_dir published_at, created_at, updated_at, title, id (asc/desc) Maps strictly to pre-compiled prepared SQL statements (use data).
page, per_page page >= 1, per_page in 1..100 Returns exact GrabInteger pagination counts and caches results in use cache.
